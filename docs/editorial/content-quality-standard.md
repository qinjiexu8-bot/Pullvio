# Pullvio 内容生产与发布质检规范

版本：1.0  
生效日期：2026-07-29

## 1. 基本原则

Pullvio 的文章服务于真实用户问题，不以批量覆盖关键词为目的。每篇文章只能有一个清晰的核心问题、一个主要搜索意图和一个对应的工具页面。能够在同一篇中完整回答的近义问题，不拆成多个页面。

AI 可以辅助研究、整理和校对，但不能代替真实测试、产品理解与编辑判断。文章不得虚构测试、用户案例、数据、个人经历或平台行为。

## 2. 选题门槛

文章进入写作前必须具备：

- 一个来自 GSC、产品失败记录、用户反馈或可验证 SERP 的长尾问题；
- 一个与问题匹配的主要关键词，而不是关键词列表；
- 与已有工具页、指南和文章不同的搜索意图；
- Pullvio 当前功能能够提供的真实下一步；
- 明确的不支持范围和授权边界。

不发布以下内容：

- 只替换平台名、格式名或语言的模板页；
- 与现有文章答案高度重复的关键词变体；
- Pullvio 当前不支持的平台或功能教程；
- 无法核实的“无水印”“最高画质”“100% 成功”等承诺；
- 为达到固定字数而扩写的段落。

## 3. 一手证据要求

每篇文章至少包含两类一手证据：

1. 当前 Pullvio 页面或处理流程的真实截图；
2. 可核实的产品行为、界面状态、错误边界或编辑观察。

写作时使用“我们在 Pullvio 当前界面中观察到……”等可验证表述。只有完成真实测试并记录环境、日期和结果后，才可以使用“我们测试了……”。

截图必须：

- 来自当前线上或待发布版本；
- 不包含邮箱、账号、任务 ID、访问令牌等隐私信息；
- 展示与文章问题直接相关的界面；
- 具有描述性 alt 文本；
- 具有解释截图意义的图注；
- 在界面发生实质变化后重新检查。

## 4. 写作标准

- 前 100–150 词直接回答核心问题；
- 文章长度由问题决定，通常为 800–1,500 个英文单词的等效信息量；
- 每个章节只处理一个子问题；
- 段落通常为 2–4 句，长短自然变化；
- 使用具体界面名称、状态和操作，不写空泛建议；
- 结尾给出明确的下一步，不重复全文；
- FAQ 仅在存在尚未被正文回答的真实相关问题时添加；
- 外部事实优先引用平台官方帮助中心或技术文档。

## 5. “去 AI 味”检查

出现下列情况即退回修改：

- “在当今数字化时代”“无论你是……还是……”等通用开场；
- 每篇文章使用相同的开头、标题数量、列表和结尾；
- 大量对称排比、同长度段落或机械式过渡；
- 反复解释同一观点；
- 没有证据的宏大判断或营销形容词；
- 把搜索结果重新拼接，却没有 Pullvio 的观察和判断；
- 为关键词密度牺牲自然语言；
- 假装作者具有未发生的个人经历。

编辑应主动保留有判断力的句子，例如说明某个“修复方法”为什么不会生效、什么时候应该停止重试，或为什么私人内容不应由下载工具绕过。

## 6. SEO 与内链

每篇文章必须通过：

- 标题、H1 与主要问题一致；
- meta description 清楚说明能解决什么；
- 主要关键词自然出现在标题、开头和至少一个正文标题中；
- 不与对应工具页争夺平台级交易词；
- 包含 2–5 个有上下文的内部链接；
- 指向一个匹配的平台工具页；
- canonical、hreflang、发布日期和修改日期正确；
- BlogPosting 与 Breadcrumb 结构化数据有效；
- 图片文件名、alt 和图注准确；
- 进入 sitemap 的仅为批准发布的文章。

## 7. 本地化标准

英文、简体中文和西班牙文版本需要传达相同事实，但不要求逐句对应。每种语言都应使用当地用户自然的设备、菜单和搜索表达。不得使用未经人工检查的直译标题或关键词堆砌。

若某一语言版本没有通过自然度和事实一致性检查，则整篇文章保持草稿状态，不单独发布其他语言。

## 8. 发布状态

- `draft`：写作或截图未完成；
- `in_review`：内容已完成，等待质检；
- `approved`：内容、SEO、事实、截图和三语版本全部通过；
- `rejected`：存在重复、事实风险或无法提供真实增量价值。

只有 `approved` 状态且带有质检日期、规范版本和审核结论的文章可以出现在公开 Blog、首页推荐、结构化数据和 sitemap 中。

## 9. 质检清单

### 内容

- [ ] 一篇只解决一个核心问题
- [ ] 首段给出直接答案
- [ ] 没有虚构测试、数据或经历
- [ ] 包含 Pullvio 一手观察与截图
- [ ] 明确说明支持与不支持边界
- [ ] 无模板化和填充性段落

### SEO

- [ ] 搜索意图与文章格式匹配
- [ ] 未与工具页或已有文章关键词冲突
- [ ] title、description、H1 和标题层级正确
- [ ] 内链、canonical、hreflang 与 schema 正确
- [ ] 图片 alt 与图注有信息价值

### 本地化与安全

- [ ] 三种语言自然、事实一致
- [ ] 没有隐私信息或密钥
- [ ] 不鼓励绕过私人内容、DRM、付费墙或访问控制
- [ ] 不承诺来源不存在的画质、格式或成功率

### 技术

- [ ] 单元测试、类型检查、Lint 和构建通过
- [ ] 内部链接无 404
- [ ] 桌面端与移动端截图检查通过
- [ ] sitemap 仅包含批准文章

## 10. 发布后复盘

发布后按 7 天、28 天和 90 天检查 GSC：

- 曝光查询是否符合原定问题；
- 页面是否与工具页发生关键词互抢；
- CTR、平均排名和工具页点击是否改善；
- 新出现的用户问题是否适合扩充原文；
- 内容或截图是否因平台和产品变化而过期。

优先更新已有文章。只有出现新的、独立搜索意图时才创建新页面。
